Overview

Simulating algorithmic collusion in real-time browser WebAssembly

The Duopoly Pricing Engine explores how autonomous Q-learning agents interact in repeated Bertrand competition with differentiated goods. Built to run entirely client-side, the engine compiles a full Python economic simulation environment and reinforcement learning agents into WebAssembly via Pyodide. Users can manipulate market structural parameters including cost asymmetries, product differentiation, demand intercept, and learning hyperparameters in order to observe price trajectories, convergence speed, and tacit collusion in real time.

Near-native Python reinforcement learning running entirely in the browser. Tightly integrated with React to provide instant economic benchmark updates and trajectory analysis without server round-trips.

How it works

Bridging React state and Python WASM through explicit dict boundaries

The application separates frontend state management from backend algorithmic execution. React controls send structured configuration payloads containing market parameters and simulation run criteria across the Pyodide WebAssembly bridge. Python converts incoming JS objects into native dictionary structures, unpacking them into frozen dataclasses. The core simulation generates a dynamic action space spanning from cost floor to monopoly price, runs memory-1 Q-learning updates over thousands of episodes, tracks optimal action streaks for convergence detection, and returns structured time-series trajectories back to TypeScript for UI rendering.

Technical decisions

Why these choices

Executive light theme for regulatory standards
Adopted a publication-grade light theme utilizing deep slate structure and high-contrast sapphire accents. This aligns with courtroom and regulatory hearing standards (e.g., European Commission DG COMP and UK Competition Appeal Tribunal proceedings), ensuring high legibility under ambient lighting and clean PDF exhibit exports.
Single dictionary bridge payload over positional arguments
Replaced positional JS-to-Python function parameters with a single nested JavaScript payload object ({ market, run }). Unpacking via Python **kwargs eliminates ordering mismatch bugs and simplifies parameter expansions.
Explicit Pyodide .to_py() conversion
Converted incoming JS proxies using .to_py() at the Python entry boundary before argument unpacking. This resolves CPython JsProxy subscripting limitations and enables standard dictionary indexing and kwarg constructor unpacking.
Factory methods & frozen dataclasses
Encapsulated market and run parameter parsing inside immutable @dataclass(frozen=True) structures with from_dict and from_params factory methods. This isolates engine defaults and type coercion from execution loops.
Fast sub-millisecond WASM benchmark derivation
Exposed a lightweight get_summary_prices Python hook alongside the main simulation engine. Sub-millisecond execution allows React useEffect hooks to re-calculate analytical Bertrand and Monopoly benchmarks instantly upon slider drag without triggering full Monte Carlo runs.
Proper Pyodide memory cleanup via .destroy()
Implemented strict try...finally resource management on all Pyodide proxy references (pyProxy.destroy()) in TypeScript. This prevents WebAssembly linear memory leaks during rapid slider interactions and parameter sweeps.
Vectorized NumPy linspace action grids
Constructed continuous price spaces using np.linspace(p_min, p_max, n_prices) in MarketSimulation.from_params. Dynamically scaling discrete action matrices based on cost bounds ensures mathematical rigor across arbitrary cost setups.
