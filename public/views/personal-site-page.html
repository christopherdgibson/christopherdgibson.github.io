Overview

Built from scratch without frameworks or templates

This site is itself a portfolio piece. Every component, including the responsive navbar, the animated hamburger sweep, the SPA routing system, the mobile overlays, is custom-coded in TypeScript without any UI framework or library. The one exception is Vite, used purely as a build tool to compile and bundle the TypeScript. The decision to avoid a UI framework was deliberate: the site demonstrates what can be built with the fundamentals alone, minimal overhead keeps the site lean and performant, and the codebase remains fully owned and understood.

No framework to hide behind. Every behaviour is written, understood, and intentional.

Features

What's under the hood

✦
What is a hamburger? Click to find out! →Hamburger sweep animation
On mobile, opening the nav wipes a light overlay across the header name. Each letter transitions to the accent blue with a staggered delay, sweeping right to left on open, and left to right on close. This is achieved with per-character span injection and CSS transitions.
🔀
SPA view loading
Views load as HTML fragments swapped into a placeholder, with a callback system that runs page-specific initialisation after each swap. Css transitions on heavier elements to smooth loading and prevent flash of unstyled content. Element and image loads awaited before scroll to top to prevent half-loaded content and ensure accurate sizing.
🧭
Client-side routing
Built on the History API directly. Correct back/forward behaviour, direct URL entry, and refresh handled via a custom 404 fallback, since GitHub Pages has no server-side routing of its own.
🪞
A site within itself
The "View Live Site" button renders a live, independent instance of this same site inside an overlay. Same router, same view-loading logic, scoped to its own container for scrolling and navigation state.
📱
Responsive at every width
The navbar collapses to a slide-out vertical menu on Click to try the mobile version! →mobile. The sub-menus expand over content on desktop and slide-out from alternating directions on mobile. Feature cards pop out with a dimmed background overlay on mobile hover, resolving the ambiguity between decorative borders and clickable links.
🖼️
Screenshot carousel
Project pages include a scrollable screenshot carousel with left/right chevron navigation. Screenshots can be viewed inline in the hero or expanded to a full overlay. Images are cropped consistently using object-fit and object-position to maintain a uniform hero height across varying screenshot dimensions.
⚡
SVG performance strategy
SVG icons are loaded from separate files to keep markup clean, with deliberate exceptions for performance. Persistent header, footer, and scroll-to-top SVGs are hard-coded inline on the index page to eliminate flash on initial load for above-the-fold elements.
🎬
Curtain navigation

Technical decisions

Why these choices

No framework
Demonstrates command of fundamentals. Every behaviour is written from first principles with nothing delegated to a library whose internals are opaque.
SPA view loading
Fragment swapping with a per-view callback system and an image-load wait before scrolling, so navigation never shows a flash of unstyled content.
Client-side routing
Click to learn more about the process of building a router! →Built on the History API directly with pushState/popState, container-scoped rendering (used by the embedded mini-site), and a 404-redirect fallback for direct URL entry and refresh on a static host with no server-side routing.
TypeScript + Vite
Written in TypeScript for compile-time safety. Catches invalid view names and unsafe DOM access before they reach the browser. Vite compiles and bundles the build; GitHub Actions runs the build and deploys automatically on push.
SVG strategy
Lazy-loaded SVGs for non-critical icons keep markup clean. Hard-coded inline SVGs for above-the-fold elements eliminate flash on first load.
Base callbacks
A shared initialisation system runs on every page load. Each function checks for its target elements before running. Pages that don't need a feature pay only a null check.
Mobile overlays
Feature card hover borders read as links on touch devices, so a pop-out overlay with dimmed background resolves the link/decoration ambiguity without changing the desktop experience.
Declarative navigation
Footer back/next buttons are configured via hidden data-attributes on each page and read dynamically on load. Each page owns its navigation content while events handlers are assigned centrally.
